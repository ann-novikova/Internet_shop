## Описание проекта "Веб-страницы"

Данное описание отражает этапы создания и настройки Django-проекта 
"Веб-страницы К", включающего приложения `catalog` и `blog`.

## Описание проекта

Проект реализует главную страницу, страницу продуктов/статей и страницу контактов.

## Техническая реализация

Проект разработан на Django с использованием:
- Встроенной системы аутентификации
- Кастомных прав доступа
- Групповых политик
- Автоматических обработчиков


**1. Git и организация разработки:**

*   Создан файл `.gitignore` для исключения ненужных файлов из отслеживания (например, файлов виртуального окружения, файлов `.pyc`, файлов `.sqlite3`, папки `__pycache__` и т.д.). 
*   Организована разработка в соответствии с моделью GitFlow:
    *   Созданы основные ветки `main` и `develop`.
    *   Для решения задач (в частности, для выполнения домашних заданий) создавались отдельные feature-ветки, ответвляющиеся от `develop` и имеющие префикс `feature/`.

**2. Оформление проекта и документация:**

*   Создан и оформлен файл `README.md` с подробным описанием проекта "Веб-страницы Каталога". Файл содержит информацию о структуре проекта, используемых соглашениях по именованию и ссылки на документацию.

**3. Создание и настройка приложения `catalog`:**

*   Создано новое Django-приложение под названием `catalog` с помощью команды `python manage.py startapp catalog`.
*   Приложение `catalog` зарегистрировано в настройках проекта (в `INSTALLED_APPS` в файле `BASE_DIR/settings.py`). В список `INSTALLED_APPS` добавлена строка `'catalog'`, указывающая на конфигурацию приложения.
*   Настроена маршрутизация для приложения:
    *   Создан файл `urls.py` в директории приложения `catalog`.
    *   В главном файле `BASE_DIR/urls.py` проекта добавлено подключение маршрутов приложения `catalog` с использованием функции `path` и `include`.

**4. Создание шаблонов:**

*   Создана директория `templates` внутри директории приложения `catalog`. В файле `settings.py` указан путь к этой директории для Django-шаблонизатора.
*   Внутри директории `templates` созданы HTML-шаблоны:
    *   `home.html` - шаблон для домашней страницы со списком товаров.
    *   `base.html` - базовый шаблон для дочерних шаблонов с повторяющимся кодом.
    *   `product_details.html` - шаблон для  подробного описания товара.
    *   `product_confirm_delete.html` - шаблон для подтверждения удаления товара.  
    *   `product_form.html` - шаблон формы для создания и обновления товара.   
    *   `contacts.html` - шаблон для страницы с контактной информацией.
*   Шаблоны стилизованы с использованием CSS-фреймворка Bootstrap.  Подключение Bootstrap CSS (и JavaScript, если необходимо) выполнено через CDN в шаблонах.
*   Обеспечена базовая структура HTML-документов, включающая `<!DOCTYPE html>`, `<html lang="ru">`, `<head>` и `<body>`.

**5. Реализация формы и валидаторов (Forms):**

Реализована форма для добавления и редактирования товара при этом добавлены валидаторы:
* исключены запрещенные слова, которые нельзя использовать в названиях и описаниях продуктов;
* цена продукта не может быть отрицательной;
* загружаемые изображения имеют формат JPEG или PNG и не превышают размер 5 МБ.

Формы соответствуют общей стилистике платформы.

**6. Реализация контроллеров (Views):**

*   В файле `views.py` приложения `catalog` созданы три контроллера (view functions):
    *   Контроллер для отображения домашней страницы (`home` или аналогичное название). Этот контроллер возвращает отрендеренный шаблон `home.html` с помощью класса `ProductListView`.
А также показывает информацию о всех товарах.
    *   Контроллер для отображения подробной информации о товаре (`product_details`).
    *   Контроллер для создания товара (`product_create`).
    *   Контроллер для обновления товара (`product_update`).
    *   Контроллер для отображения страницы с контактной информацией (`contacts_view` или аналогичное название). Этот контроллер возвращает отрендеренный шаблон `contacts.html` с помощью функции `render`.

**7. Настройка маршрутизации для контроллеров:**

*   В файле `urls.py` приложения `catalog` настроена маршрутизация для контроллеров с использованием функции `path`:
    *   Определен URL-путь для домашней страницы (например, пустая строка `''`, `'home/'`, `'/'`), который связан с контроллером `home`.
    *   Определен URL-путь для страницы контактов (например, `'contacts/'`), который связан с контроллером `contact`.

**8. Запуск проекта и доступ к страницам:**

*   Для запуска проекта необходимо перейти в директорию, содержащую файл `manage.py` (обычно это корень проекта `CatalogWeb`), и выполнить команду `python manage.py runserver`.
*   Доступ к домашней странице осуществляется по адресу `http://127.0.0.1:8000/products` (или другому адресу, указанному в выводе команды `runserver`).
*   Доступ к странице контактов осуществляется по адресу `http://127.0.0.1:8000/contacts/`.

**9. Реализация приложения `blog`:**

Модель для блоговой записи имеет следующие поля:

* заголовок,
* содержимое,
* превью (изображение),
* дата создания,
* признак публикации (булевое поле),
* количество просмотров.

Для работы с блогом реализован полный CRUD для новой модели, используя CBV.
Модифицирован вывод и обработку запросов, добавив следующую логику на уровне контроллеров:
1. Увеличение счетчика просмотров: при открытии отдельной статьи увеличивается счетчик просмотров.
2. Фильтрация опубликованных статей: выводиться в список статей только те, которые имеют положительный признак публикации.

**10. Приложение для работы с пользователями:**

Модель пользователя использует электронную почту как поле для авторизации. Также добавлены дополнительные поля:
* аватар (изображение),
* номер телефона,
* страна.

***Регистрация пользователя:***

Создана форма для регистрации пользователя с полями электронной почты и пароля.
Добавлена логика регистрации в представлении, позволяя пользователю создать учетную запись.
Реализована отправка приветственного письма пользователю после регистрации.

***Авторизация пользователя:***
Настроена форма и представление для авторизации пользователя по электронной почте и паролю.
Закрыт доступ к страницам, связанным с управлением продуктами, для анонимных пользователей. 
Только авторизованные пользователи могут просматривать, создавать, изменять и удалять продукты. 
Общедоступной достается только страница просмотра списка товаров.


Авторизация пользователя:
Настройте форму и представление для авторизации пользователя по электронной почте и паролю.

Также добавлен интерфейс редактирования профиля пользователя.

**11. Реализация настройки прав пользователей:**

Создана группа для роли «Модератор продуктов» и настройте необходимые разрешения: 
* Разрешение can_unpublish_product
* Разрешение на удаление любого продукта.

Создание продукта настроено таким образом, чтобы автоматически привязывать продукт к авторизованному пользователю.
При создании нового продукта поле owner автоматически заполняется текущим авторизованным пользователем.
Настроены проверки в контроллерах, чтобы только владелец мог редактировать и удалять продукт.

Создана группа для роли «Контент-менеджер».Пользователи, которые включены в эту группу, могут управлять публикациями 
в блоге. Реализованы проверки, чтобы обычный пользователь или модератор из другого отдела не мог изменять раздел блога.

**12. Клонирование проекта и установка зависимостей (инструкция):**

Для получения локальной копии проекта из удаленного репозитория (например, GitHub) и установки всех необходимых зависимостей, выполните следующие шаги:

1.  Убедитесь, что у вас установлен Git.
2.  Откройте терминал или командную строку.
3.  Перейдите в директорию, куда вы хотите склонировать проект, используя команду `cd <путь_к_директории>`.
4.  Выполните команду `git clone <URL_репозитория>`.
    Пример: `git clone https://github.com/ann-novikova/Internet_shop.git` (замените URL на фактический URL вашего репозитория).
5.  После завершения клонирования, в указанной директории будет создана папка с названием репозитория, содержащая все файлы проекта.

имеет понятный `README.md`, а также файл `requirements.txt`, облегчающий установку необходимых зависимостей.
